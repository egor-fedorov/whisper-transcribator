# 0.5.0
Native Windows, macOS and Linux ARM64 distribution for the local C++17/whisper.cpp CLI, with the same sequential transcription, bounded audio windows and resumable jobs. Docker remains optional packaging of the same executable; archives need neither Python nor an external ffmpeg executable.

## Highlights
- Add Windows x64 and ARM64 CPU ZIPs, macOS Apple silicon CPU/Metal and Linux aarch64 CPU archives alongside Linux x86_64 CPU/CUDA.
- Select portable Windows ARM64 CPU plugins using processor-feature probes: baseline NEON, DOTPROD, FP16 and I8MM variants. macOS includes Accelerate, Metal and Apple CPU variants; Linux ARM64 includes baseline through SVE2/SME variants.
- Support outputs, model caches and resumable progress on FAT32, exFAT and other filesystems without POSIX permissions or hard links. Warn when checkpoint privacy depends on mount options, and guard batch output collisions on case-insensitive filesystems.
- Use the selected thread count for whisper.cpp VAD rather than its fixed four-thread default, avoiding severe overhead on some low-core and non-OpenMP configurations.
- Add experimental Linux/Windows x64 Vulkan archives with explicit `--device vulkan`. It is not selected by `auto`; explicit GPU initialization failure never silently falls back to CPU. Native Windows GPU execution and AMD/Intel hardware remain unvalidated.
- Separate application settings, audio components, checkpoint storage, rendering, platform code and test infrastructure. Preserve CLI behavior and durable formats while documenting module responsibilities and testing their boundaries.
- Require CUDA and Linux Vulkan hardware verification of the exact release archives before hosted draft creation. The GPU runner builds CUDA and checks both GPU archives; the GitHub-hosted publisher uploads eight archives and two verification reports after approval.

## Archives
Names use `whisper-transcribator-0.5.0-` followed by the suffix below. Keep `bin/`, `lib/` and `share/` together; these are relocatable bundles, not universal static binaries.

| Archive suffix | Minimum system | Inference |
| --- | --- | --- |
| `linux-x86_64-cpu.tar.gz` | Linux x86_64, glibc 2.35+ | Portable CPU, including a non-AVX2 baseline |
| `linux-x86_64-cuda.tar.gz` | Linux x86_64, glibc 2.35+, compatible NVIDIA driver | CUDA and CPU fallback |
| `linux-x86_64-vulkan.tar.gz` | Linux x86_64, glibc 2.35+, compatible Vulkan driver | Experimental Vulkan (explicit selection) and CPU |
| `linux-aarch64-cpu.tar.gz` | 64-bit ARM Linux, glibc 2.35+ | Portable ARM CPU |
| `macos-arm64-metal.tar.gz` | Apple silicon, macOS 14+ | Metal and CPU/Accelerate |
| `windows-x86_64-cpu.zip` | Windows x64, Windows 10 version 1903+ | Portable x64 CPU |
| `windows-arm64-cpu.zip` | Native Windows 11 ARM64 | Portable ARM CPU |
| `windows-x86_64-vulkan.zip` | Windows x64, Windows 10 version 1903+, compatible Vulkan driver | Experimental Vulkan (GPU execution unvalidated) and CPU |

Bundles include decoding-only FFmpeg, inference/runtime dependencies, notices, corresponding dependency source archives and build provenance. Models are downloaded separately and verified by SHA-256; existing GGML model caches can be reused. CUDA runtime libraries are bundled, but the host driver is not. CUDA compilation covers SM75/80/86/89/90; one tested GPU does not certify every architecture. No container-registry images are published by this release workflow.

Vulkan archives need no SDK. Linux bundles its loader; Windows uses `vulkan-1.dll` from the installed GPU driver. Neither bundles a GPU driver. A Vulkan-capable device is not a guarantee that every backend feature works; use `doctor --device vulkan --json`. CUDA remains the established NVIDIA option.

## Upgrade Notes
JSON schema 2, checkpoint schema 3, decoding policy 1, timeline 3 and chunking 4 are unchanged from 0.4.0. There is no forced checkpoint restart solely for this application-version change. Normal source, destination, model, backend and settings compatibility checks still apply; resumed output metadata retains the original job's version. Completed transcripts and model weights are not rewritten. Older incompatible development checkpoints still require their original binary or an explicit restart.

Windows uses `%LOCALAPPDATA%\whisper-transcribator\models` by default; explicit cache options retain precedence. Input/output paths support Unicode, and longer Windows paths also require the OS long-path policy. Use numbered batch output names where filenames differ only in letter case. On filesystems without private permissions, other users may be able to read checkpoints according to mount settings.

See [installation instructions](https://github.com/egor-fedorov/whisper-transcribator/blob/v0.5.0/README.md) and [resume semantics](https://github.com/egor-fedorov/whisper-transcribator/blob/v0.5.0/docs/resume.md).

## Release Verification
Release gates require successful hosted main CI and Experimental Vulkan runs for the exact source commit, source/checksum/dependency verification of all eight archives, and separate short offline inference checks. Hosted CPU/Metal CI covers Linux x86_64/aarch64, macOS Apple silicon and Windows x64/ARM64. Windows CPU checks include Unicode paths, WAV/MP3 decoding and interrupted resume; the x64 CPU ZIP also runs in Server Core without a preinstalled VC++ runtime. Vulkan hosted archive checks are model-free, not GPU execution tests. Slow baseline-CPU QEMU inference remains a separate manual gate.

The owner-approved NVIDIA job builds the CUDA archive in the pinned CUDA 12.8.1/Ubuntu 22.04 environment and downloads the exact hosted Linux Vulkan archive without rebuilding it. Both are checked in clean offline containers using the public 11-second JFK fixture and a 41-second window/resume fixture, not full lectures or private recordings. `cuda-verification.json` and `vulkan-verification.json` record archive SHA-256, source revision, selected GPU and successful checks. They are required before draft creation, not independent cryptographic attestations. No additional manual/local GPU archive check is required. Publication remains a separate owner action.

## Known Limitations
- Windows binaries are not Authenticode-signed. Smart App Control can block the executable or DLLs; checksums do not bypass this policy. SignPath integration is pending ([#36](https://github.com/egor-fedorov/whisper-transcribator/issues/36)). Do not disable system-wide protection; use WSL if permitted or wait for a signed distribution.
- macOS bundles have ad-hoc signatures, no Apple Developer ID or notarization. Browser-downloaded archives may require handling Gatekeeper quarantine as documented in the README; managed machines may forbid them.
- Windows CUDA, Windows ARM64 GPU/NPU acceleration, Intel Mac archives and 32-bit ARM are not provided. Windows Vulkan GPU execution and AMD/Intel hardware are not yet validated; the optional Vulkan archives remain experimental.
- A window without a safe segment boundary can still use a warned hard cut ([#17](https://github.com/egor-fedorov/whisper-transcribator/issues/17)). Inference can appear idle without progress callbacks, and timestamp corrections suppress an unreliable ETA ([#18](https://github.com/egor-fedorov/whisper-transcribator/issues/18), [#27](https://github.com/egor-fedorov/whisper-transcribator/issues/27)).
- Truncated audio can finish without a reliable missing-tail warning; decode diagnostics are not persisted in transcript JSON ([#25](https://github.com/egor-fedorov/whisper-transcribator/issues/25)). Unusable decoded frames can still fail resampler setup in tolerant mode ([#26](https://github.com/egor-fedorov/whisper-transcribator/issues/26)). Recovery cannot restore lost speech.
- No parallel file jobs, diarization, word timestamps or automatic lecture summaries. Windowing is not a hard RAM/VRAM cap; full model hashing and small persistent lock files remain intentional.
